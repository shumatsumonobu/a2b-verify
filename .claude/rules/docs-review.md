# ドキュメントのレビュー観点

README などを書いたり直したりしたあと、公開の前に通す観点 ── 文体の決まりは [CLAUDE.md](../../CLAUDE.md) の文体の節

## 進め方

- 自分の目で頭から通読する ── 置き換えのスクリプトや grep で済ませない
- 機械のチェック（links.py、check_readme.py、句点と記号の検査）は通読のあと
- 1か所直したら、同じ型が他に無いかを全体で探す
- 初めて来た他人のつもりで読み、止まったところを全部書き出してから直す
- 改行コードを変えない（Write で書き直すと LF になる）

## 読み手と置き場所

- README は訪れた人のための場所 ── 運用する側の情報（スクリプトの手順、環境、照合の仕組み）は verify/README.md と CLAUDE.md に置く
- 冒頭で、読者が持ち帰れるものを伝える ── 太字の1文と「この資料が答える問い」に、何が手に入るかを書く
- 読者が期待しないものを冒頭に置かない ── このリポジトリに無い道具（自分のサービスを調べるツールなど）を期待させる書き方をしない

## 言葉

- 何の〜かを書く ── 作り方、試し方、原文、各見出し、残りの4件、同じ仕組み、書き忘れ、通す、などを単独で使わない
- 内輪の言葉と専門用語は、初めて出る場所で補う ── 一次情報、二次情報、コントロール、恒久対策、IoC、認可、など
- 主語をずらさない ── 1文の中で主語が入れ替わらないか、資料や文書が人の動作の主語になっていないか（この資料で読んで、など）
- 位置や番号で指さない ── 下の、最初の表、ではなく、見出しやリンクで指す
- 1文に同じ語を2回使わない
- 言い回しが自然か ── このページの使い方、引用が本物、のような、意味は分かるが引っかかる言い方を直す

## 原文の扱い

- 原文は折りたたまずにその場に出す ── 原文と同じことを言うだけの要約は書かず、何の原文かを言う導入を1行置く
- 1つのテーマの原文は、1つの引用ブロックにまとめる
- 引用の中で Markdown の箇条書きを使わない ── 原文の記号（•）で始まる行にする
- 原文のぼかし（おそれがある、など）を、要約で言い切りに変えない
- 書いていない、と言うときは、確かめた範囲を書く（通読1回、など）

## 段落と改行

- 行末のスペース2つの改行は、役割の違う行を分けるときだけ使う
- ひと続きの話は1文にまとめ、並んでいるものは箇条書き、主張・理由・根拠のように役割が違うものは入れ子の箇条書きにする
